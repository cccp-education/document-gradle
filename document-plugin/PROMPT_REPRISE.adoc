== Pièges Gradle à retenir (S-232..S-249)

1. *Snapshot collect* : `collectDocumentRetrieve` re-scan à chaque exécution
   (`outputs.upToDateWhen { false }`) — pas de `@InputFile` du rapport.
2. *mustRunAfter inverse la CLI* : conflit d'inputs si 2 tâches partagent
   un build.
3. *Chaîne N3 staged* : produce → validate → collect (3 builds).
4. *Property DSL sans convention reste unset même derrière `.orElse(...)`*.
5. *Dérivation knob sans dépendance de tâche* : jamais provider vers
   `outputFile` du producteur, jamais `.get()` configuration-time.
6. *`@InputFile` valide l'existence AVANT l'action* — porter les chemins
   audités en `@Input @Optional Property<String>` (pattern `htmlFilePath`
   / `epubFile` / `pdfFile`).
7. *`--tests` Gradle ne réduit PAS la découverte Cucumber* — filtrer côté
   annotation du runner (`FEATURES_PROPERTY_NAME`).
8. *Imports DSL consommateur* (S-239) : les enums des gardes ne sont pas
   résolus implicitement — importer explicitement côté `build.gradle.kts`
   tiers. Liste dans README.md (six gardes, à jour S-247).
9. *epubcheck callback Java → null* : signature nullable obligatoire.
10. *Preuve négative : corrompre la STRUCTURE, pas le contenu* (EPUB :
    mimetype OCF ; PDF : voir #14 — les octets sont tolérés).
11. *Polling Central* : `<latest>` peut rester périmé ~27 min — tester aussi
    le HTTP 200 du POM versionné.
12. *Test bakery JBake native roundtrip périmé* : `50_jbake_native_translation.feature:22`
    attend `:summary:` verbatim mais document traduit `summary`/`description`
    depuis S206. Préexistant — à mettre à jour côté bakery.
13. *Drift catalogue ws* : MEMPHIS bump le catalogue en amont — la garde
    `DocumentPluginPublicationTest` RED au prochain build. Fix : bump des
    2 pins (settings D4 + platform BOM) vers la version publiée Central.
14. *PDFBox 3.x lénient sur les octets* (S-247) : header corrompu → WARNING
    + charge quand même ; xref tronqué → reconstruction. Le garde PDF est
    un garde *texte extractible par page*. Preuve négative = pages sans
    texte, jamais des octets.
15. *`PDPageContentStream.setFont(PDFont, float)` 2 params* (S-247) :
    l'erreur Kotlin `No value passed for parameter 'p1'` vient du size
    manquant, pas de la résolution `PDType1Font(FontName)`.
16. *Drift jar Central ↔ mavenLocal sous le MÊME numéro* (S-248) :
    `publishToMavenLocal` met à jour l'artefact local sans changer la
    version — Central peut être en retard. Un consommateur DOIT déclarer
    `pluginManagement { repositories { mavenLocal() } }` AVANT le Plugin
    Portal pour tester le HEAD local ; sans lui, Gradle résout
    silencieusement depuis Central et rate les gardes récentes
    (symptôme : `Task 'validateDocumentPdf' not found` malgré le JAR).
17. *Central exige une version explicite par dépendance POM* (S-249,
    pattern S-209) : une dep `implementation` sans version (résolue par
    platform BOM) produit un POM sans `<version>` → rejet nmcp AUTOMATIC
    `Dependency version information is missing`. Fix : alias `libs.*`
    avec version.ref dans le catalogue local du borough (12 deps
    basculées S-249). Toute nouvelle dep doit suivre ce pattern.

== Anti-glue Cucumber (règle de propriété — S-238)

Chaque feature a UN runner propriétaire. Le runner global (glue
`document.scenarios`) ne découvre que `document.feature` +
`release-notes.feature` + `frontmatter_retranslate.feature`. Toute
nouvelle feature doit soit rejoindre un runner dédié (pattern : runner +
glue + tag + CucumberTaskSpec dans build.gradle.kts), soit explicitement
rejoindre le global avec ses steps dans `document.scenarios`.
Le 18e runner dédié est `pdfCheckCucumberTest` (S-247).
