= Cadrage EPIC DOC-BOOK-TRANSLATE — Traduction du livre structuré

_Date_ : 2026-09-26
_Borough_ : New Orleans (document-gradle)
_Origine_ : demande pilote — « est-ce que document intègre bien le livre avec la TOC avec la traduction ? »
_Statut_ : ✅ TERMINÉ (S-267 cadrage, S-268 US-1, S-269 US-2→US-5, S-270 US-6)
_Pattern_ : S-057/S-063 (gouvernance pure) + baby-step DDD/TDD/BDD strict

== Contexte

Le borough sait **assembler** un livre structuré (`BookTocParser` →
`BookTreeBuilder` → `BookAssembler`, EPIC DOC-BOOK-DOMAIN), l'**illustrer**
(DOC-BOOK-IMAGES), le **paginer** (DOC-BOOK-MATTER), le **naviguer**
(DOC-BOOK-CONSISTENCY-B6) et le **publier** dans 6 formats. Il sait aussi
**traduire** de l'AsciiDoc (EPIC DOC-TRANSLATE, `AsciiDocParser` →
`DocumentTranslator`/`TreeTranslationAdapter`).

Mais les deux chaînes sont **étanches** : aucune référence croisée entre
`document/translation/` et le domaine `document` « Book », dans un sens comme
dans l'autre. Le livre n'est **pas traduit**, et le brancher naïvement sur la
chaîne existante **détruirait la structure** que DOC-BOOK-CONSISTENCY-B6 vient
de stabiliser.

== Décisions architecturales

. *D1 — Traduire AU NIVEAU DU DOMAINE BOOK, pas en étendant le pivot*
  (option B retenue, option A écartée). La structure du livre est *générée* par
  `BookAssembler` à partir de l'arbre (constat #4) : traduire l'AsciiDoc
  assemblé puis le re-parser avec le pivot lossy (constat #2) reviendrait à
  détruire ancres/doctype/TOC. On traduit les **entrées** (titres + corps), puis
  `BookAssembler` **régénère** la structure à l'identique.

. *D2 — Unité de traduction = titre de nœud + corps de page*. Les titres
  viennent de `BookSection.title`/`BookNode.title` ; les corps de la résolution
  existante (`ContentPageResolver`/`BookPageRenderer`). Chaque corps est un
  fragment sans construction de livre (constat #5) → le pivot existant suffit.

. *D3 — Réutiliser intégralement la chaîne de traduction existante*
  (`TranslationService` N0, `DocumentTranslator`/`TreeTranslationAdapter` pour
  les corps, `PlantUmlTranslationAdapter`, validation tableaux/PlantUML). Zéro
  nouveau bridge LLM, zéro nouveau contrat N0, zéro bump BOM.

. *D4 — Réutiliser `BookAssembler` pour le ré-assemblage*. Aucun nouvel
  assembleur : le `BookLayout` (matter, navigation, images, toc) est réappliqué
  à l'identique. Les ancres `[[ref]]` et les refs ne sont **jamais** traduits
  (identifiants structurels, pas du texte).

. *D5 — Le domaine porte un service `BookTranslator` pur* (Gradle-free) :
  `translate(tree, resolveContent, srcLang, tgtLang)` → `TranslatedBook`
  (arbre aux titres traduits + résolveur de corps traduits). Unit-testable sans
  TestKit, avec un `TranslationService` fake. Le wiring Gradle reste dans la
  tâche.

. *D6 — Nouvelle tâche `translateBook`* produisant `book-<lang>.adoc`
  (miroir du nommage multi-langue de capsule). Inputs `pagesDir`, `tocFile`,
  `photosDir`, `sourceLanguage`, `targetLanguage`, `llmMode` ; `@Input @Optional`
  pour les chemins (piège S-232 #3), `@DisableCachingByDefault` (LLM
  non-déterministe — non-incrémentable).

. *D7 — Navigation, xref et TOC traduits par construction*. La traduction des
  titres suffit : `toc::[]` rend les headings traduits, `navigationLinks` et
  labels `<<ref,title>>` lisent `BookSection.title` traduit, les refs restent
  valides (constat #7). Le gate dogfooding vérifie : 0 ancre dangling, N cibles
  == N ancres.

. *D8 — Économie d'Encre : traduction metered*. `translateBook` est opt-in et
  `skipExisting` (la sortie `book-<lang>.adoc` existante n'est pas retraduite).
  Le delta fin par bloc (`BlockDelta`, déjà existant) est un EPIC ultérieur —
  hors périmètre de cet EPIC (constat : un livre est traduit une fois, pas
  retouché bloc à bloc aussi souvent qu'un article).

. *D9 — Multi-langue additif*. Le premier jet traduit UNE langue cible
  (property `targetLanguage`). L'extension N langues (`translateToAll` dérivé de
  `LanguageCatalog` N0, pattern `capsule.multilang`) est une US ultérieure.

. *D10 — Backward compat totale*. `book { targetLanguage }` défaut vide = pas
  de traduction ; `bookPipeline` sans langue = pipeline actuel inchangé ;
  aucun convertisseur, aucun contrat N3, aucune tâche existante modifiés.

. *D11 — Boundary respectée*. Règle 7 (jamais muter les scans source — lecture
  seule, sortie sous `build/`), Règle 8 (Document = WRITE + PUBLISH ; Codex =
  READ). Aucune dépendance codex.

. *D12 — Méthode baby-step DDD/TDD/BDD stricte* : UT (domaine pur, fake) → FT
  (TestKit) → BDD (runner dédié `@book-translate`, 23e) → dogfooding réel sur le
  corpus. English only.

. *D13 — Non-goals explicites* : (a) pas d'extension du pivot aux constructions
  de livre (option A rejetée, D1) ; (b) on ne touche pas au pivot consommé par
  bakery (risque de régression) ; (c) pas de delta bloc-à-bloc dans cet EPIC
  (D8) ; (d) pas de traduction côté codex/RAG.

| Option | Principe | Verdict

  renderers, puis traduire tout le livre assemblé en un passage.
| ❌ *Écartée*. Touche un modèle partagé avec bakery, risque de régression

  artefact délicat. Coût/bénéfice défavorable pour un besoin book-scoped.

document {
    book {
        pagesDir.set(file("src/book/pages"))
        tocFile.set(file("src/book/toc.adoc"))
        sourceLanguage.set("fr")     // Property<String>, défaut "fr"
        targetLanguage.set("en")     // Property<String>, défaut "" = pas de traduction

> défaut vide (pas de traduction).

== Gates et risques

* *Gate structurel* (le cœur de l'EPIC) : le livre traduit porte le **même
  nombre d'ancres** `[[ref]]` que la source, `:doctype: book`, `toc::[]`, et
  **0 ancre dangling** — preuve exécutable que D1 (traduire le domaine, pas le
  texte assemblé) préserve la structure.
* *Gate non-régression* : les 22 runners Cucumber existants restent verts, la
  baseline UT/FT est préservée, `bookPipeline` sans langue est byte-identique.
* *Risque #1 (LLM metered)* : un livre ≈ 200 pages → coût réel. Mitigation :
  opt-in, `skipExisting`, dogfooding sur fixture réduite d'abord.
* *Risque #2 (fidélité OCR)* : les marqueurs `[ILLISIBLE]` du corpus pourraient
  être traduits. Mitigation : les marqueurs OCR vivent sur la **source**
  (`book-ocr-issues.json`, non traduit) ; la fidélité du marqueur dans le livre
  traduit est un point de test (classifier non-traduisible si nécessaire).
* *Risque #3 (continuité multi-pages)* : une phrase à cheval sur deux scans est
  traduite par fragment. Accepté (miroir du comportement batch) ; documenté.
* *Risque #4 (couplage format)* : nul — D1 évite tout parsing du livre assemblé.
