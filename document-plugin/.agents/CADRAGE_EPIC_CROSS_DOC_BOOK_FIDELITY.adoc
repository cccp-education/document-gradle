= CADRAGE EPIC — CROSS-DOC-BOOK-FIDELITY : le BDD cross-borough teste le contrat réel
:epic: CROSS-DOC-BOOK-FIDELITY
:date: 2026-09-24
:pattern: S-057/S-063 (gouvernance pure) + baby-step BDD strict

== Contexte

L'EPIC `CROSS-DOC-BOOK` (S-210) a livré un filet BDD cross-borough
(`cross_borough_book.feature`, 4 scénarios, runner `CrossBoroughCucumberRunner`).
Ces scénarios sont **verts** et référencés `✅ TERMINÉ` dans le BACKLOG.

Une revue d'ouverture (S-263) révèle que ces scénarios **ne testent pas le
contrat réel** : ils valident une *fiction* qui passerait même si le pont
codex→document était cassé.

== Décisions architecturales

. *EPIC BDD-only* — aucun code de production modifié. Le pont filesystem
  fonctionne ; la valeur est la **garantie contractuelle fidèle**.

. *Fidélité producteur* — les fixtures reproduisent la sortie codex réelle :
  pages `.adoc` **sans en-tête**, contenu brut. Une page dont le contenu
  contient `=` ne doit pas fabriquer d'en-tête.

. *Chemin de production couvert* — un scénario lit une TOC (format
  `| Référence | Sujet / Titre | Page | Fichier`), la parse
  (`BookTocParser`), construit l'arbre (`BookTreeBuilder`) et assemble via
  `contentAwareResolver` — exactement le chemin de `AssembleBookTask`.

. *Section multi-pages* — une ligne TOC `Page = 5, 6` + deux fichiers codex
  `005-*.adoc, 006-*.adoc` produit **un** en-tête (section logique) et
  **deux** contenus concaténés dans l'ordre.

. *Assertions sur le contrat, pas sur la fixture* — compter/en vérifier les
  en-têtes doit prouver un comportement de l'assembleur (en-tête dérivé de la
  TOC), jamais une donnée injectée par la fixture.

. *Runner/steps propriétaires conservés* — feature `cross_borough_book.feature`,
  glue `document.crossborough`, runner `CrossBoroughCucumberRunner`, tâche
  `crossBoroughCucumberTest`. Tag `@cross-borough @book-pipeline`.

. *Pas de nouvelle feature/runner* — on étend le contrat existant
  (économie d'encre, pas de duplication de glue).

. *Baby-step BDD strict* — un scénario à la fois : RED
  (`UndefinedStepException`) → GREEN (PASSED) → REFACTOR (`check` VERT).
  English only.

== Gates et risques

* *Gate* : `crossBoroughCucumberTest` VERT, scénarios fidèles PASS, aucune
  régression des 22 runners Cucumber.
* *Risque faible* : test-only. Si `BookAssembler` change de comportement
  (en-tête dérivé de la TOC, concaténation multi-pages), le BDD casse — c'est
  le but (regression guard fidèle).
* *Non-régression* : zéro code de production modifié ; la feature existante
  est corrigée, pas dupliquée.
