== Mission session 223

Corriger le « bruit » du moteur Cucumber global du borough (`DuplicateStepDefinitionException`).
Diagnostic corrigé en cours de session : la cause RÉELLE n'est PAS le plugin conventions
(`education.cccp.build.cucumber` 0.0.2) — son classpath doublonnait seulement le `jar` projet
(redondant avec `main.output`, inoffensif). La vraie cause était une **étape Cucumber dupliquée
dans les tests document-gradle** :

- `a document gradle project with no converter configuration` était définie dans DEUX classes de
  steps : `IncludeGuardSteps.kt` (package `document.includeguard`) ET `ConverterSafeModeSteps.kt`
  (package `document.convertersafemode`).
- Le moteur Cucumber GLOBAL (sans restriction `glue` + tâche `SecurityPolicyCucumberRunner` sans
  `glue`) scanne tout le classpath → `io.cucumber.core.runner.DuplicateStepDefinitionException`.
- Les runners DÉDIÉS (`IncludeGuardCucumberRunner`, `ConverterSafeModeCucumberRunner`) restreignent
  `glue` à leur package → masquaient le doublon.

Fix (commit `f67eb8e`, poussé) : textes de step distincts (`no include guard configuration` /
`no safe mode configuration`) + features mises à jour. Vérifié : `securityPolicyCucumberTest`,
`includeGuardCucumberTest`, `converterSafeModeCucumberTest` → BUILD SUCCESSFUL (PASSED, plus de
DuplicateStepDefinitionException).

Hygiene conventions (commit `1c13b7e`, poussé dans conventions-gradle) : `CucumberConventionsPlugin`
et `build.gradle.kts` du plugin utilisent `testRuntimeClasspath + test.output + main.output`
(suppression du `jar` redondant) + test fonctionnel de régression `CP_JAR_PRESENT=false`.
