== Contexte

_Règle pilote_ : « Le pont N2↔N2 entre codex (Brooklyn) et document
(New Orleans) est le filesystem. Les deux boroughs sont parallèles N2,
pas empilés. Le contrat est le format `%03d-%s.adoc` — codex produit,
document consomme via `BookAssembler`. »

Ce pont existe et fonctionne (US-CDX-13-3 S-075, `CollectOcrPagesContractTest`
+ `BookAssemblerTest`). Mais il n'existe aucun scénario Cucumber
end-to-end qui valide la chaîne complète `collectOcr → assembleBook → convert`.

== Décisions architecturales

. *EPIC BDD-only* — ce cadrage ajoute des tests, pas du code
  production. Le pont filesystem fonctionne déjà. La valeur est la
  garantie contractuelle.

. *Cucumber feature côté document* — le scénario vit dans
  `document-gradle` (consommateur). Le producer (codex) est simulé
  via des fichiers `.adoc` in-memory dans `DocumentWorld`. Pattern :
  même logique que `createGradleProjectWithOcrPagesAndSourcePointingToBook()`
  (S-011 existant).

. *Runner dédié* — nouveau `CrossBoroughCucumberRunner` + tâche
  `crossBoroughCucumberTest` dans `build.gradle.kts` document.
  Pattern S-082 (runner dédié par domaine). Tag `@cross-borough`.

. *Steps dédiés* — `CrossBoroughSteps.kt` dans package
  `document.crossborough`. Préfixe « cross-borough » dans tous les
  step defs (bug S-088 — glue partagée).

. *Pas de dépendance Gradle codex↔document* — la test setup
  reproduit le format de sortie codex sans importer codex. Le test
  valide le *contrat*, pas l'*implémentation*.

. *KDoc clarification* — ajouter une `@see BookAssembler` dans le
  KDoc de `CollectOcrTask.outputDir` (codex) et documenter le format
  `%03d-%s.adoc` comme contrat formel. Pas de constante partagée
  (overkill pour un format filesystem).

. *Pas de tâche runner-gradle* — l'orchestration `collectOcr →
  assembleBook` est hors scope de cet EPIC. Elle fera l'objet d'un
  EPIC futur si besoin (suggestion : `RUN-BOOK-PIPELINE`).

. *Baby-step TDD/BDD strict* — RED (UndefinedStepException) → GREEN
  (scénarios PASSED) → REFACTOR (`check` VERT). 1 scénario à la fois.
  English only.

== Gates et risques

* *Gate* : Aucune. Le pont filesystem fonctionne déjà. Les tests
  valident un contrat existant.
* *Risque faible* : le scénario (c) (dégradé silencieux) dépend du
  comportement actuel de `BookAssembler` qui skip les fichiers vides.
  Si le comportement change, le test casse — c'est le but (regression
  guard).
* *Non-régression* : aucun code production modifié. Le
  `crossBoroughCucumberTest` est ajouté au `check` mais ne touche pas
  aux scénarios existants.
