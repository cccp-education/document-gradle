= CADRAGE EPIC DOC-XREF-VALIDATE — Validation des références croisées AsciiDoc

_Session_ : 224 (New Orleans 🟢)
_Borough_ : document-gradle (N2 — WRITE + PUBLISH)
_Famille_ : VALIDATE (parallel à DOC-TABLE-VALIDATE / DOC-PLANTUML-VALIDATE / DOC-CR4 / DOC-CR5)
_Méthode_ : baby-step DDD/TDD/BDD strict (unit + functional + cucumber)
_Loi Economie d'Encre_ : validateur DDD pur, zéro I/O, zéro Gradle — idempotent.

== Constat (prémisse)

Le Domaine « Book » (`BookTree`, `BookNumbering.anchor(ref)` → `[[ref]]`,
`BookAssembler` émet des ancres `[[ref]]` pour chaque section) produit des livres
AsciiDoc riches en ancres de navigation. Mais *rien* ne vérifie aujourd'hui que les
références croisées `<<ref>>` (ou `xref:ref[]`) présentes dans le contenu pointent
vers une ancre définie. Un `<<id>>` orphelin produit un lien mort dans le HTML/PDF/EPUB
final — défaut silencieux, invisible au build, détectable seulement par lecture humaine.

Cas d'usage : livre FPA (203 pages, TOC riche) — un `<<1.2.3>>` pointant vers une
section renommée casse la navigation du livre publié.

== Décision architecturale

. *Package* `document.xref` (parallel à `document.security`, `document.translation.validation`).
. *Mode* `XrefValidationMode` enum { OFF, STRICT, LENIENT } — parallel à `IncludeGuardMode`.
  Défaut OFF (backward-compatible). Câblé dans le bloc `converter { xrefValidation = ... }`
  (mirror flat `xrefValidation`) + CLI `-Pdocument.xrefValidation`.
. *Sévérité* : STRICT → `GradleException` fail-fast ; LENIENT → `logger.warn` ; OFF → no-op.
  Appliquée dans `ConvertDocumentTask.convert()` *avant* la conversion (parallel à
  `DocumentIncludeGuard.check`), et dans une tâche dédiée `validateDocumentXref` qui émet
  un rapport JSON `xref-validation-report.json` (parallel à `TableValidationReport`).
. *Extraction AsciiDoc* (heuristique regex sur le texte brut, parallel à `IncludePathValidator`
  qui scanne aussi le brut) :
  - Ancres définies : `[[id]]`, `[[id,label]]` (ancre inline/bloc), `[#id]` (id de bloc).
  - Références : `<<id>>`, `<<id,text>>`, `xref:id[]`, `xref:id[text]`.
  - IDs = `[A-Za-z0-9_][A-Za-z0-9_.\-]*` (accepte les `ref` hiérarchiques `1.2.3`).
. *Hors périmètre* : auto-IDs générés par Asciidoctor depuis les titres de section
  (implicites, non écrits dans le source) — on ne valide que les ancres explicites.
. *Zéro nouveau knob DSL/CLI* hors `converter { xrefValidation }` (compose avec safeMode/includeGuard).
