== Patterns partagés (DRY cross-EPIC)

.`ValidationMode` enum — commun aux 2 EPICs
[source,kotlin]
----
enum class ValidationMode { STRICT, LENIENT, OFF }
----

.`ValidationResult` sealed — pattern commun
[source,kotlin]
----
sealed class ValidationResult {
    data class Valid : ValidationResult()
    data class Invalid(val reason: String, val context: Map<String, String>) : ValidationResult()
}
----

.Structure de test — 3 niveaux systématiques
- UT : value objects purs, sans dépendance externe
- FT : Gradle TestKit, vérifie le wiring CLI
- BDD : Cucumber, scénarios end-to-end avec fake LLM

1. VALIDATE-1 — TableSyntaxValidator (5 pts, ~15-20 UT) :
   - Créer document/translation/validation/TableSyntaxValidator.kt
   - Value object DDD pur, zéro dépendance externe
   - Méthode : fun validate(table: Table): TableValidationResult
   - TableValidationResult sealed : Valid / Invalid(articleTitle, tableIndex, reason)
   - Règles :

     a) Convertir le PivotBlock.Table traduit en Table via parseTableStructured()
     b) Appeler TableSyntaxValidator.validate()
     c) Si Invalid : logger un warning avec contexte (article title, table index, reason)
        Ne PAS bloquer la traduction des autres blocs
     d) Si Valid : continuer normalement
   - Tests : 8-10 UT (mock validator, warning propagation, valid table no-op,
     table with corrupted delimiter after translation, table with column mismatch)

Vérification : ./gradlew test --tests "document.translation.validation.*" --offline

== Points d'attention transverses

. *ValidationMode* — créé dans S035, réutilisé tel quel dans S038 (pas de duplication)
. *ValidationResult sealed* — pattern commun, chaque EPIC a sa propre sealed class
   (contexte différent : TableValidationResult vs PlantUmlValidationResult)
. *DSL translation { }* — les 2 blocs tableValidation { } et plantumlValidation { }
   cohabitent dans DocumentExtension.kt
. *Batch report* — seul TABLE-VALIDATE a un batch report (VALIDATE-4).
   PLANTUML n'en a pas (les diagrammes sont moins nombreux, le log suffit)
. *Dépendance plantuml-plugin* — passe de compileOnly à implementation (S038).
   Vérifier que ça ne casse pas les tests existants (PlantUmlTranslationAdapter
   utilise déjà plantuml-plugin en compileOnly)
