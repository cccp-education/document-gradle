== Travail effectué

=== DOC-CR3-1 — Réutiliser l'instance AsciidoctorJ (P1) ✅

*Constat* : `DocumentConverter.kt:106,128` appelait `Asciidoctor.Factory.create()`
à chaque conversion (`.use { }` fermait l'instance après chaque appel). Pour le
bookPipeline (5 formats), cela démarrait JRuby 5× par livre.

*Décisions* :
- Nouveau `object AsciidoctorHolder` (package `document`) : instance unique
  créée paresseusement, mise en cache, réutilisée pour toutes les conversions.
- Accès `synchronized(lock)` (l'instance AsciidoctorJ n'est pas garantie
  thread-safe).
- Seam de test : `setProviderForTest(...)` / `resetProvider()` (internal) pour
  injecter un provider compteur et prouver la réutilisation.
- `DocumentConverter.convert` / `convertToFile` délèguent désormais à
  `AsciidoctorHolder.convertFile(...)`. API publique inchangée.

*Baby-step TDD strict* :
- RED : `AsciidoctorHolderTest` (1 test) → compile fail (`AsciidoctorHolder`
  inexistant).
- GREEN : création du holder + refactor converter → assertion
  `createCount == 1` PASSED.
- REFACTOR : `DocumentConverterTest` + `AsciidoctorHolderTest` verts
  (non-régression, `--rerun-tasks`).
