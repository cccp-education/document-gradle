== Piège découvert (S-282) — pollution mavenLocal par `publishToMavenLocal`

En recompilant document, le build a cassé (`Unresolved reference
'SyntaxValidationResult'`) : le `publishToMavenLocal` **plantuml 0.0.5** exécuté
en US-2 (avant bump du catalogue) avait **écrasé** le `0.0.5` local avec le code
de HEAD (type `SyntaxValidationResult` supprimé), alors que le `0.0.5` **Central**
le contient encore. Document résout `mavenLocal()` en premier → build cassé.

**Remède** : restaurer `0.0.5` depuis Central (jar/pom/module) dans
`~/.m2` → build VERT. **Leçon** : ne **jamais** `publishToMavenLocal` une version
**déjà publiée Central** sans bump — cela écrase silencieusement la release locale
et crée un split code↔Central. (Nouveau piège à consigner.)
