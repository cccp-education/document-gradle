== Réalisation

=== DOC-CR4-1 — DDD `document.security` (TDD strict) ✅

Nouveau package `src/main/kotlin/document/security/` :

- `IncludeGuardMode.kt` — enum { STRICT, LENIENT, OFF } (défaut OFF).
- `IncludeDirective.kt` — data class (raw, target, line).
- `IncludeValidationResult.kt` — sealed Valid / Invalid(reason, offendingTarget, line).
- `IncludePathValidator.kt` — object :
  * `parseIncludes(text): List<IncludeDirective>` (regex
    `include::\s*("(?:[^"]*)"|[^\[\s]+)(\s*\[[^\]]*\])?`).
  * `validate(text, baseDir, allowedRoot = baseDir): IncludeValidationResult` —
    rejette chemin absolu et chemin traversant (`..` sortant de `allowedRoot`).
- `DocumentIncludeGuard.kt` — object `check(text, baseDir, mode, onWarn)` :
  OFF → no-op ; STRICT → `GradleException("Include guard (STRICT) rejected conversion — ...")`
  ; LENIENT → `onWarn("Include guard (LENIENT) — ...")`.

Tests : `src/test/kotlin/document/security/IncludePathValidatorTest.kt` — 12 UT (absolu,
relatif traversant, relatif valide sous baseDir custom, escaping, multi-includes, numéros de
ligne, off no-op, lenient warn, strict throw, regex edge). TDD RED → GREEN. `test` VERT.

=== Bug préexistant corrigé (S-221)

`registerBookPipeline` overridait **inconditionnellement** `convertDocumentToHtml.sourceFile`
sur le livre assemblé (`build/docs/document/book.adoc`) via `html.configure { it.sourceFile.set(...) }`,
rendant la conversion standalone (`document { source = ... }`) impossible (input file manquant).
Corrigé : l'override n'est appliqué **que si `bookPipeline` est dans le task graph** —
`project.gradle.taskGraph.whenReady { if (graph.hasTask(bookPipeline)) { html/pdf/epub... } }`.
Conversion standalone rétablie ; `bookPipeline` préserve son comportement (4 FT safeMode GREEN).
