== Livré — DOC-BOOK-PUBLISH US-5 (knob `includeSource`, décision D8)

Le fan-out de publication (`publishBookAllLanguages`, S-272) publiait uniquement
les livres **traduits** (`book-<lang>.adoc` × format). Le livre source assemblé
(`book.adoc`) restait hors du fan-out, couvert par les seuls convertisseurs
mono-source. US-5 ajoute le knob **opt-in** `includeSource` : quand il est actif,
le livre assemblé est publié lui aussi (`book.<ext>`, sans suffixe de langue),
**en première position** du plan (ordre déterministe).

=== US-5-1 — domaine pur `BookPublicationPlanner` (TDD, RED → GREEN)

* `BookPublicationTarget` gagne un champ additif `isSource: Boolean = false` —
  backward-compatible (les cibles traduites restent `false` par défaut).
* `BookPublicationPlanner.plan(...)` gagne 2 paramètres additifs
  (`sourceLanguage: String = ""`, `includeSource: Boolean = false`) et émet, en
  tête, une cible `<base>.adoc` → `<base>.<ext>` par format quand l'opt-in est
  actif. Un `includeSource` sans format reste un **no-op strict** (Économie
  d'Encre). Le domaine reste Gradle-free et pur.
* RED prouvé : 6 nouveaux tests → `No parameter with name 'includeSource'`
  (`compileTestKotlin` FAILED). GREEN après extension du domaine.

=== US-5-2 — tâche + DSL + N3 + wiring

* `PublishBookAllLanguagesTask` : propriété `@Input includeSource` (défaut
  `false`), transmise à `BookPublicationPlanner.plan` dans l'action.
* `DocumentPlugin.registerPublishBookAllLanguages` : CLI
  `-Pdocument.bookPublishIncludeSource` > DSL, et **dépendance conditionnelle**
  `assembleBook` (le livre source est produit par `assembleBook`) — ajoutée
  *uniquement* quand `includeSource` est actif, via un `provider`, pour que le
  graphe par défaut reste **byte-identique** (aucune tâche amont surprise).
  `@OutputFiles` (piège #40) reflète le plan étendu.
* DSL : `BookDsl.includeSource` (+ convention `false`) + mirror flat
  `DocumentExtension.bookPublishIncludeSource`.
* N3 : `BookConfig.includeSource` (additif, `null` omis) +
  `SerializeDocumentConfigTask.bookPublishIncludeSource` + sérialisation /
  désérialisation `document-config.json` (round-trip idempotent préservé).

=== US-5-3 — BDD `@book-publish` (3 scénarios, runner existant)

Le runner `bookPublishCucumberTest` (25e) possède déjà la feature : pas de
nouveau runner (Économie d'Encre). 3 scénarios ajoutés + 3 steps préfixés
`book-publish` (anti-collision S-088) : source non publiée par défaut,
`includeSource` publie la source en tête de plan, no-op sans format.

=== US-5-4 — FT dogfooding offline (corpus réel réduit, Règle 7)

Nouveau FT `BookPublishContentFunctionalTest` : sur un sous-ensemble réel borné
du corpus privé, `publishBookAllLanguages` avec `includeSource=true` produit
`book.html` (source non traduite — porteuse du contenu, **sans** marqueur
`[EN]`) **et** `book-en.html` (traduite), `assembleBook` est bien exécuté.
Preuve TestKit additionnelle (livre synthétique) : `includeSource` publie
`book.html` + `book-en.html` et planifie `assembleBook` ; sans le knob,
`book.html` absent et `assembleBook` hors graphe.
