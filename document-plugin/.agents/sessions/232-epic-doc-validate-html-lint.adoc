== Résumé livré

La validation composite `validateDocument` orchestre désormais **quatre** gardes au lieu de trois :
include guard (CR4) + xref (CR-xref) + security policy (CR5) + **HTML link lint du rendu**
(DOC-HTML-LINT, S-226). Le rapport consolidé `document-validation-report.json` porte un 4e bloc
`htmlLint` (`status` VALID/DEAD, `deadLinks`), symétrique du bloc `xref`.

=== US-1 (TDD strict) — 4e garde dans le domaine pur

- `DocumentValidator.validate(...)` étendu : paramètres `htmlLintMode: HtmlLinkLintMode = OFF`
  + `html: String? = null` (defaults backward-compat, les 5 appels existants compilent sans changement).
- `HtmlLintReportEntry` (status/deadLinks/reason, `@JsonInclude(NON_NULL)` — `deadLinks` nullable :
  null pour VALID, liste triée pour DEAD).
- `DocumentValidationReport.htmlLint: HtmlLintReportEntry? = null` + `@JsonInclude(NON_NULL)` sur la
  classe conteneur → JSON backward-compat (bloc absent en OFF).
- `overallStatus()` étendu : `htmlLint.status == "DEAD"` → FAIL (un lien mort casse la navigabilité
  N3 quel que soit le mode — visibilité même en LENIENT).
- `fromJson` backward-compat : rapport sans `htmlLint` → `null`, PASS.
- Règle « HTML absent sous mode non-OFF » : `DEAD` avec entry `<html-file-missing>` (visibilité sur
  silence, jamais de skip muet).
- 10 UT `HtmlLintGuardTest` (RED : `No parameter with name 'htmlLintMode'` → GREEN).

=== US-2 (FT TestKit) — câblage tâche + plugin

- `ValidateDocumentTask` : inputs `htmlLinkLint` (Property) + `htmlFilePath` (`@Input @Optional`
  String — volontairement PAS un `@InputFile` : Gradle validerait l'existence du fichier absent
  avant l'action, brisant le rapport consolidé en STRICT), lecture optionnelle du HTML, sévérité
  STRICT fail-fast / LENIENT warn / OFF skip (même contrat que xref).
- `DocumentPlugin.registerValidateDocument` : mode depuis `converter { htmlLinkLint }` + mirror flat
  + CLI `-Pdocument.htmlLinkLint` (même knob que `lintHtmlDocument`, zéro nouveau concept) ; chemin
  HTML résolu depuis la convention statique de sortie `build/docs/document/document.html` (parité
  lecture-seule metadata-validation) ; `mustRunAfter("convertDocumentToHtml")`.
- Enseignements de câblage (3 pièges Gradle corrigés en itération) :
  1. `Property<RegularFile>` → le provider du producer crée une **dépendance implicite** : lancer
     `validateDocument` seul déclenchait `convertDocumentToHtml` (échec include-guard STRICT avant
     écriture du rapport) → snapshot de la valeur du chemin à la configuration.
  2. `.get()` sur `outputFile.map{}` à la configuration → `Querying the mapped value ... before the
     task has completed is not supported` → chemin résolu depuis le layout (convention statique).
  3. `@InputFile @Optional` non-null → `Input file does not exist` bloquant → `@Input @Optional`
     String (le fichier absent est un finding, pas une erreur).
- 4 FT `ValidateDocumentTaskHtmlLintFunctionalTest` (OFF skip / STRICT fail + DEAD + liste fragment /
  STRICT pass + VALID / LENIENT warn) — RED puis GREEN.
