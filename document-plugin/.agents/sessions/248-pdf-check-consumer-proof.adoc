== Constats

=== 1. Drift jar Central ↔ mavenLocal (constat clé de la session)

Le `<latest>` Central et mavenLocal portent le MÊME numéro de version 0.0.15,
mais les deux jars divergent :

- *JAR Central 0.0.15* (publié S-241, avant S-247) : **zéro** classe
  `ValidateDocumentPdfTask` (vérifié `unzip -l` sur le jar téléchargé repo1).
- *JAR mavenLocal 0.0.15* (republié par S-247 via `publishToMavenLocal`) :
  2 classes `ValidateDocumentPdfTask` + câblage `registerValidateDocumentPdf`
  (vérifié javap bytecode : l'appel est bien dans `apply()`).

Cause : S-247 a publié vers mavenLocal sans publication Central (accord pilote
requis, Règle 2). Le POM mavenLocal porte bien platform 0.0.31 + pdfbox runtime
(epubcheck, gems) — cohérent S-247.

*Leçon (nouveau piège #16)* : `publishToMavenLocal` met à jour l'artefact
local **sous le même numéro de version** — le mavenLocal est TOUJOURS la
vérité du HEAD, jamais Central. Un consommateur sans `pluginManagement {
mavenLocal() }` en tête de repositories résout silencieusement depuis Central
et rate les gardes récentes (piège #8 S-239 est le symptôme consommateur du
même phénomène pour les imports).

=== 2. Preuve consommateur — 4/4 scénarios VERTS (mavenLocal)

Projet tiers `/tmp/opencode/doc-consumer-pdf` (Gradle 9.7.1 wrapper du
borough, JDK 25, `pluginManagement { mavenLocal() }`) consomme
`id("education.cccp.document") version "0.0.15"` :

. *Résolution* : `buildEnvironment` → `document-plugin:0.0.15` ; preuve

  Maven repository 'MavenLocal'` — la garde `validateDocumentPdf` est

. *Scénario 1 (VALID)* : `convertDocumentToPdf validateDocumentPdf

  `pdf-validation-report.json` `{"tool":"pdfbox","entries":[{"status":"VALID"}]}`.
. *Scénario 2 (preuve négative discriminante)* : PDF 2 pages sans texte
  (produit via un helper Java PDFBox one-shot, zéro Python) placé sous
  `outputFileName=textless` → STRICT BUILD FAILED avec
  `pdf validation failed (STRICT): page 1: no extractable text, page 2:
  no extractable text` + rapport INVALID portant les 2 issues. LENIENT →
  build vert + même rapport INVALID. OFF → skip (pas de réécriture du
