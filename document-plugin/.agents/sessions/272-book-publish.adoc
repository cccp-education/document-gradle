== Découvertes / pièges

* *Le fan-out de langues était déjà là* — `translateBookAllLanguages` (S-271)
  fournit le plan de langues ; la publication doit le **réutiliser** (même plan,
  jamais recomputé) via `dependsOn`. Zéro second catalogue (D2).
* *Le moteur de conversion était dupliquable* — les 5 tâches mono-source
  recopient la logique `DocumentConverter` (header metadata / sidecar). La
  nouvelle tâche appelle `DocumentConverter` directement (DRY) — pattern
  `BookTranslationRunner` (S-271).
* *`@OutputFiles` dynamique (piège #40)* — le répertoire `docs/document/` est
  partagé ; un `@OutputDirectory` créerait un conflit de sorties. La collection
  `@OutputFiles` peuplée par un provider reflète le plan exact.
* *`bookPipeline` intact* (D10) — la nouvelle tâche reste autonome (non ajoutée
  au composite) : non-régression stricte du pipeline historique.

== ⚠️ Découverte majeure — CI document-gradle rouge EN CONFIGURATION (préexistante)

Le run CI déclenché par le push S-272 (`36352150595`, commit `8676baf`) échoue
**avant toute compilation** :

----
* What went wrong:
ossrhUsername not found
BUILD FAILED in 7s
----

*Ce n'est PAS un échec de session.* Audit de l'historique GitHub Actions :
**100 % des runs échouent** depuis ≥ 2026-09-14 avec le même message (S-261,
S-262, S-263, S-264, S-265, S-266, S-267, S-268, S-269, S-270, S-271 — tous
`failure`). Cause racine : `settings.gradle.kts` évalue
`nmcpSettings { centralPortal { username = globalProps.getProperty("ossrhUsername")
?: error("ossrhUsername not found") } }` au **configuration time**, sur *toute*
invocation (`./gradlew build` compris). Le runner GitHub n'a pas de
`~/.gradle/gradle.properties` → échec avant les tests.

*Conséquence* : **aucun test document-gradle ne s'exécute en CI depuis ~2
semaines** — la règle « Local = Build, Tests = CI » est neutralisée, et toute la
dette aval est masquée (leçon bakery `BKY-CI-ISOLATION`, S-243 : « une CI morte
en configuration masque toute la dette aval »).

*Correctif candidat (hors périmètre S-272 — Règle 2)* : EPIC **DOC-CI-ISOLATION**
— rendre les identifiants nmcp **optionnels à la configuration** (exiger
seulement au moment de `publish*`, pas au `build`) ; éventuellement fournir les
credentials via secrets GitHub Actions. À cadrer sur accord pilote.
