== Livré

=== US-2 — tâche `translateBook` (3 pts) ✅

* Domaine : `TranslateBookTask` (`@DisableCachingByDefault`, LLM non
  déterministe). Inputs `pagesDir`/`photosDir`/`tocFile` (`@Input @Optional`
  pour les chemins, piège S-232 #3), `title`, `author`, `sourceLanguage`,
  `targetLanguage`, `llmMode`, `skipExisting`, plus `matterPolicyMode`,
  `matterBreaks`, `navigation` (parité de layout avec `assembleBook`).
* La tâche traduit le **domaine** (`BookTranslator`) puis **régénère** la
  structure (`BookAssembler`) : ancres `[[ref]]`, `:doctype: book`, `toc::[]`,
  navigation préservés **par construction** (décision D1).
* Sortie `book-<lang>.adoc` dérivée du knob `outputFileName` (S-259) —
  `book.adoc` reste intact.
* Ink Economy Law : `targetLanguage` vide ou identique = strict no-op (aucun
  appel LLM, aucune écriture) ; `skipExisting` ne réécrit pas une traduction
  existante.
* DSL `book { sourceLanguage; targetLanguage }` (conventions `fr` / `""`) +
  mirror flat `bookSourceLanguage`/`bookTargetLanguage` + CLI
  `-Pdocument.bookTargetLanguage` + `-Pdocument.bookSourceLanguage`.
* Contrat N3 : `BookConfig.sourceLanguage`/`targetLanguage` additifs +
  `DocumentConfigSerializer` (round-trip idempotent préservé).

=== US-3 — insertion `bookPipeline` (2 pts) ✅

* `bookPipeline` dépend de `translateBook`. Quand une langue cible est
  configurée, les convertisseurs HTML/PDF/EPUB consomment `book-<lang>.adoc`
  (sortie de `translateBook`) au lieu de `book.adoc` — le pipeline publie le
  livre traduit. Sans langue cible, comportement byte-identique (backward
  compat).
* L'ordre est fixé **au configuration time** (`mustRunAfter`) : un
  positionnement en `taskGraph.whenReady` arrive trop tard (le graphe est déjà
  ordonné) — leçon documentée (nouveau piège #36).
* Preuve dogfooding manuelle : `bookPipeline` sur un projet TestKit →
  `document.html` porte bien `Part I [EN]`.

=== US-4 — BDD `@book-translate` (2 pts) ✅

* Feature `book_translate.feature` 5 scénarios (titres+corps traduits, refs
  intacts ; ancres/doctype/toc régénérés ; navigation sur titres traduits ;
  cible vide = no-op ; source == cible = no-op).
* `BookTranslateSteps` (préfixe `book-translate `, anti-glue S-088) +
  `BookTranslateCucumberRunner` (**23e runner dédié**) + `CucumberTaskSpec`
  `bookTranslateCucumberTest`. 5/5 PASSED.

=== US-5 — dogfooding + découverte bug parser (1 pt) ✅

* Gate structurel sur le **corpus FPA réel** (116 sections, 200+ pages) :
  traduction FR→EN via un `FakeTranslationService` déterministe (aucun coût
  LLM metered — Règle 2). Preuve : même nombre d'ancres que la source,
  `:doctype: book`, `toc::[]`, **0 cible de navigation dangling** (vérifiée
  structurellement via `BookNumbering`, pas par regex sur la prose OCR).
* **Bug P0 découvert** — le parser pivot NPE (`Regex(...).find(line)!!`) sur
  toute ligne commençant par `=` mais qui n'est pas un titre AsciiDoc : les
  flèches OCR (`=> …`) et marqueurs parasites (`=*`, `====`) du corpus réel.
  Fix TDD strict (RED NPE prouvé → GREEN) : nouveau `isHeading(line)` +
  `HEADING_PATTERN` companion, appliqué dans `parseBlocks` ET dans la garde
  d'arrêt de `parseParagraph`. 2 UT `AsciiDocParserTest` de verrouillage.
