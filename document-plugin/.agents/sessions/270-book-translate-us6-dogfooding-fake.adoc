=== Découverte — ancre in-band OCR et lossiness du pivot

La première exécution a **échoué** (RED authentique, pas un faux positif) :
le `book.adoc` source portait `[[page-10]]`, une ancre **in-band** au tête du
scan `010.adoc` — **non structurelle**. Le livre traduit l'a perdue : le
`BookTranslator` route le corps de page dans le pivot (`parseBody`), qui est
*lossy* sur les constructions de livre (constat #2 du cadrage, la raison même
de D1). Le gate D1 légitime porte sur les **refs structurelles de la TOC**
(générées par `BookAssembler`), jamais sur une égalité byte-à-byte du jeu
d'ancres. Le test a été affiné en conséquence :

----
val missing = tocRefs - anchorRefs(translated)
assertTrue(missing.isEmpty(), ...)   # portée = refs structurelles, pas artefacts OCR
----

C'est une caractérisation **précieuse** : elle documente que la traduction du
corps (pivot) peut perdre un artefact d'ancre OCR, ce qui est acceptable (le
livre reste navigable par construction), et interdit un gate trop strict.
