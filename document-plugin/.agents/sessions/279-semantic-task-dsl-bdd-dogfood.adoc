=== Découverte CI (run `37051193960`, commit `2b3451d`) — bug de configuration

La première CI de clôture a **échoué** (`functionalTest` : 13 échecs, dont les
4 nouveaux `CollectTableSemanticsFunctionalTest` + des FT préexistants
`DocumentPluginFunctionalTest`/`AssembleBookTaskFunctionalTest`/…). La cause est
**unique et systémique** : le plugin ne se **configure** plus du tout.

* Erreur : `Could not create task ':collectTableSemantics' > DefaultTaskContainer#NamedDomainObjectProvider.configure(Action) on task set cannot be executed in the current context.`
* Cause : `registerCollectTableSemantics` appelait
  `project.tasks.named("collectDocumentRetrieve").configure { … }` **à
  l'intérieur** de l'action passée à `tasks.register("collectTableSemantics")`.
  Une action de `register` s'exécute en différé ; y imbriquer un
  `named(…).configure` viole le contrat de cycle de vie Gradle.
* Correctif : déplacer le `named("collectDocumentRetrieve").configure { … }`
  **hors** de l'action `register` (configuration time). Le reste du registre
  (task wiring) est inchangé ; `compileKotlin` VERT revérifié.
* *Leçon* : une CI rouge à la **configuration** (pas à l'exécution) invalide
  *tous* les FT — le diagnostic se fait par la première exception, pas par le
  compteur d'échecs. Nouveau piège **#53**.

== Pièges / notes

* *`ListProperty<Custom>` exige `Serializable`* — `SemanticTableSchema` /
  `SemanticColumnSpec` l'implémentent (sinon `IllegalStateException` à la
  configuration Gradle).
* *Runner non câblé = test fantôme* — le 28e runner devait être enregistré dans
  `build.gradle.kts` (`additionalTasksInCheck = true`) pour s'exécuter en CI
  (leçon S-269).
* *`logger`, pas `log.lifecycle`* — `log` est un SLF4J `Logger` (pas de
  `lifecycle`) ; les messages de cycle de vie passent par `logger.lifecycle`.
* *Le dogfooding annote une copie, jamais l'original* — `replaceFirst("|===", …)`
  sur une copie du fichier privé (Règle 7), hash vérifié.
* *Cucumber `{string}` ne décode PAS `\n`* — la feature passe l'échappement
  littéral ; le step doit le convertir (`replace("\\n", "\n")`) sinon le texte
  écrit n'a pas de vrais sauts de ligne et l'AST ne voit aucun tableau. Les
  steps sœurs (`xref`) ne l'exigeaient pas (leurs assertions ne dépendent pas du
  découpage ligne) ; le parsing tabulaire, si. Nouveau piège **#54**.
* *Deux modèles tabulaires parallèles* (piège #47) — l'AST (lifting) et le pivot
  regex (traduction) cohabitent, nommage sans ambiguïté.
