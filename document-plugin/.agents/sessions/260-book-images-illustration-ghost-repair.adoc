== Découverte majeure — la mécanique d'embarquement des images (S-260)

Sonde empirique (4 variantes, `DocumentConverter.convertToEpub`) : AsciidoctorJ
* n'embarque **pas** une image référencée par un chemin **absolu** (cible
  silencieusement absente → RSC-007) ;
* **rejette** (`RSC-026`, *« leaks outside the container »*) un chemin relatif
  qui **sort** du répertoire du `book.adoc` — l'EPUB est alors INVALID ;
* n'embarque et ne rend conforme (`VALID`) que l'image **située dans le
  répertoire source ou un de ses sous-répertoires**.

Décision actée (cadrage `CADRAGE_EPIC_DOC_BOOK_IMAGES.adoc` D4) : `assembleBook`
**copie** les scans réellement référencés dans `<outputDir>/images/` et émet
`:imagesdir: images` (relatif) + des cibles nues. Le livre et ses dérivés sont
auto-contenus et epubcheck-VALID. Coût maîtrisé : seuls les scans référencés
sont copiés (jamais les 525 Mo du corpus).

== Implémentation (3 US, TDD strict)

=== US-2 — Résolution des ghosts (B5), le gate EPUB

Domaine pur d'abord :
- `BookImageResolver` — résout le scan d'une page par son préfixe numérique
  (les deux conventions `61.adoc` / `001-introduction.adoc`), sonde les deux
  paddings (`61.jpg` / `007.png`) et le suffixe de découpe (`83_1`) ;
- `BookImageRewriter` — répare une directive `image::` fantôme : cible existante
  → inchangée ; cible absente + scan de page → **substitué** (formes block ET
  inline, légende et commentaire de fin préservés) ; cible absente sans scan →
  **ligne supprimée** (EPUB conforme plutôt qu'une ressource manquante).

Le doute reste *rapporté* sur la source par `BookOcrFailureDetector`
(`book-ocr-issues.json`) — réparer ≠ signaler, deux responsabilités distinctes.

*Baby-step TDD* : RED (les 2 objets inexistants, 11 tests `BookImagesTest`) →
GREEN (2 fichiers prod) → REFACTOR (découverte TDD : la découpe `055_2` devait
normaliser le zéro-padding vers `55_2`).

=== US-1 — Illustration structurée (B4)

  illustration opt-in), pour que la logique image soit *convention-agnostique* ;
