== Mission

EPIC transverse **GBL-010** (arbre de traduction du site), branche Data, **G-2** :
document possède l'article comme document et son **arbre AsciiDoc (AST)**. Le pivot
`document.translation` est une **liste plate** de blocs ; l'arbre est la forme
manquante qui les regroupe sous leurs titres et **surface les feuilles** que le
borough plantuml possède (`PivotBlock.Source(language = "plantuml")`).

Vision pilote : *« chaque article est à prendre comme un document, et chaque document
a l'arbre du document AsciiDoc (AST) dedans. On y trouvera des balises plantuml, et
ce sera le borough plantuml qui gérera sa traduction. »*

== Livrable — domaine pur `document.translation.tree.ArticleTreeAudit`

* `ArticleNode.kt` — `sealed interface ArticleNode` : `Section(level, title, children)`
  + `Leaf(kind, translatable, owner)` ; `ArticleLeafOwner` (`DOCUMENT`/`PLANTUML`).
* `ArticleTreeAudit.kt` — `build(content)` : construit l'arbre interne (sections par
  niveau de titre via une pile, feuilles regroupées sous leur section) ;
  `of(content)` → `ArticleTreeReport` (racine, `blocks`, `translatableLeaves`,
  `plantumlLeaves`, `hasDiagrams`, `render()` **déterministe** — aucun horodatage).
  Classification des blocs : `heading`/`paragraph`/`list`/`table`/`admonition`/
  `description-list`/`source`/`block-macro`/`hr` ; un `Source("plantuml")` est une
  feuille **`owner = PLANTUML`**.
* Runner dédié `ArticleTreeCucumberRunner` + `articleTreeCucumberTest` (conventions
  0.0.8, `additionalTasksInCheck = true`).
