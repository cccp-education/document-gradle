== Diagnostic (2 barrières, pas 1)

=== Barrière #1 — credentials exigés au configuration time

`settings.gradle.kts:21-27` évalue
`nmcpSettings { centralPortal { username = globalProps.getProperty("ossrhUsername")
?: error("ossrhUsername not found") } }` sur **toute** invocation — `./gradlew
build` compris. Le runner GitHub n'a pas de `~/.gradle/gradle.properties` → le
build meurt au **configuration time**, avant la moindre compilation.

Reproduction locale **fidèle** (faux `HOME`, aucun credential) :

----
$ HOME=/tmp/... ./gradlew help
* Where:
Settings file '.../settings.gradle.kts' line: 23
* What went wrong:
ossrhUsername not found
BUILD FAILED in 1s
----

C'est **le même échec** que le log CI `36352150595`.

=== Barrière #2 — la garde de publication lit un dépôt voisin

`DocumentPluginPublicationTest.wsCatalogToml()` lisait
`../workspace-bom/gradle/libs.versions.toml` (working tree du repo MEMPHIS). Sur
un **checkout CI isolé** (le repo `document-gradle` seul), ce chemin n'existe
pas → `error("ws catalog toml introuvable ...")`. Même famille que
`graphify D5-RACE` (S-029) : une garde ne lit **jamais** le working tree d'un
dépôt voisin — racy entre sessions, absent en CI.

**La barrière #1 masquait la #2** : tant que la configuration échoue, aucun test
ne tourne, donc la #2 restait invisible dans les logs. Les corriger séparément
aurait laissé la CI rouge (leçon bakery S-243 : « V1 masque V2..Vn »).

== Découverte annexe — `.gitignore` bare `build` (bug latent)

En préparant le commit, les 4 nouveaux fichiers de garde (placés initialement
dans le package `document.build`) n'apparaissaient **pas** en untracked :
`git check-ignore` a révélé que le motif `.gitignore` **non ancré** `build`
(ligne `build` du `.gitignore` plugin + `build/` de la racine) matche **tout
répertoire nommé `build` à n'importe quelle profondeur** — donc le package
source `document.build/`. **Conséquence potentielle** : une garde de test jamais
committée = une garde jamais exécutée en CI. Correctifs : (1) package source
renommé `document.ci` (un package `build` entre en collision avec le répertoire
Gradle `build/` omniprésent) ; (2) motifs **ancrés** (`/build` plugin,
`/build/` racine) pour que la cause racine ne puisse plus piéger un futur
package. Build re-vérifié VERT.

== Barrière #3 — la dette masquée (1 test réel rouge, révélé par la CI)

Le premier run CI après correctif (`36353300514`) **exécute enfin** les tests
(7m36s, **5029 tests**, 4817 skipped corpus) — l'EPIC a atteint son but. Il
révèle **1 échec réel**, jusqu'ici masqué par la barrière #1 : le scénario BDD
`@book-publish` « No language is a strict no-op » (`BookPublishCucumberRunner`).

----
org.opentest4j.AssertionFailedError: the plan must be empty, got: [book-.html]
----

*Cause racine* (bug S-272) : `BookPublicationPlanner.plan` filtrait `emptyList()`
de langues mais **pas un code de langue blanc** (`""`) — le step BDD passe
`BookLanguageTarget(code = "")`, produisant un fantôme `book-.html` au lieu d'un
no-op. Le garde-fou manquait au domaine (asymétrie avec « format inconnu
ignoré »).

*Correctif (TDD, RED prouvé par la CI)* : `plan` filtre désormais
`it.code.isNotBlank()` (un code blanc est écarté, jamais un `book-.html`
fantôme) + **2 UT** de verrouillage. Compilation VERTE ; preuve finale = run CI
suivant.
