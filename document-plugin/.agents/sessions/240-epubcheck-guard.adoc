  aucune validation de conformité EPUB nulle part.
. `org.w3c:epubcheck:5.2.1` (référence W3C, succession `org.idpf:epubcheck`)
  existe en bibliothèque Java native sur Central — zéro CLI, zéro Docker.

  EPUB binaire n'est audité par personne.

  mode/result/port/adapter/report) a été repris, épinglé et câblé.

== Résumé livré

=== US-1 (TDD, UT) — domaine `document.epub` pur + adapter épinglé

- Domaine Gradle-free : `EpubValidationMode` {OFF/LENIENT/STRICT, défaut OFF},
  `EpubValidationResult` sealed {Valid/Invalid(issues)}, port
  `EpubCheckRunner` (fun interface, stateless, ne throw jamais),
  adapter `LibEpubCheckAdapter` (bridge `EpubChecker.check()` collectant
  chaque message `ID severity: text (path:line)`, filtre
  SUPPRESSED/USAGE/INFO), `EpubValidationReport` JSON (miroir xref,
  NON_NULL).
- UT existantes (port + rapport) conservées vertes.
- UT adapter créées (`LibEpubCheckAdapterTest`, 5 tests) : fichier manquant/
  répertoire → `<epub-file-missing>`, non-EPUB → Invalid avec issues,
  EPUB3 minimal construit à la main (mimetype STORED + container + OPF +
  nav + chapter, zéro binaire versionné — économie d'encre) → Valid,
  réutilisation stateless.
- *Bug réel attrapé par le TDD* : epubcheck appelle `info(null, ...)` depuis
  Java → NullPointerException sur le paramètre Kotlin non-null `feature`.
  Fix : signature nullable (`feature: String?`). RED (2 failures NPE) →
  GREEN (17 UT epub 0 FAIL).
- Dep `org.w3c:epubcheck:5.2.1` via catalogue (`libs.epubcheck`),
  `implementation` — consommée uniquement par l'adapter. Zéro bump BOM.

=== US-2 (TDD, FT TestKit) — tâche `validateDocumentEpub` + DSL + CLI

- `ValidateDocumentEpubTask` (`@DisableCachingByDefault`) : mode
  OFF skip / LENIENT warn + rapport / STRICT fail-fast après écriture du
  rapport. EPUB absent sous mode non-OFF → rapport `Invalid
  <epub-file-missing>` + fail STRICT / warn LENIENT (miroir de la règle
  HTML-absent = DEAD S-232 — visibilité sur silence).
- *Piège S-232 #3 évité* : `epubFile` porté en `@get:Input @get:Optional
  Property<String>` (chemin) et PAS en `@InputFile` — un `@InputFile` valide
  l'existence AVANT l'action (`Input file does not exist`), ce qui interdit
  la règle « EPUB absent = finding ». Miroir exact de
  `ValidateDocumentTask.htmlFilePath` (S-232).
- Câblage `DocumentPlugin.registerValidateDocumentEpub` : chemin EPUB dérivé
  du même knob `outputFileName` que la conversion (jamais le provider
  outputFile du producteur — dépendance implicite interdite, `.get()`
  config-time interdit), mode `converter { epubCheck }` + mirror plat
  `ext.epubCheck` (défaut OFF back-compat) + CLI `-Pdocument.epubCheck`,
  `mustRunAfter("convertDocumentToEpub")` (piège S-233 #2 : mustRunAfter
  ordonne sans coupler), rapport `build/docs/document/epub-validation-report.json`.
- FT `ValidateDocumentEpubTaskFunctionalTest` 4/4 : OFF skip sans rapport /
  STRICT absent → GradleException + rapport `<epub-file-missing>` / LENIENT
  absent → warn + build vert + rapport / STRICT + EPUB fraîchement converti
  (`convertDocumentToEpub, validateDocumentEpub`) → VALID.
- Non-régression : `DocumentPluginFunctionalTest` BUILD SUCCESSFUL.

  seulement si besoin N3 réel.

  (Règle 2).

  pas régénéré (économie d'encre).
